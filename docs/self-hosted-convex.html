Architecture

Four places matter: your dev laptop, the self-hosted Convex Docker stack, Cloudflare Tunnel (public HTTPS), and Vercel (Next.js). Convex Cloud can stay idle for rollback; it is not on the live path once cut over.

FIG 3 — Deploy. Self-hosted admin key replaces CONVEX_DEPLOY_KEY. Do not mix cloud and self-hosted deploy vars.

Common mistake: leaving CONVEX_DEPLOY_KEY on Vercel while only changing NEXT_PUBLIC_CONVEX_URL. The UI then talks to self-hosted, but convex deploy still pushes functions to Convex Cloud (or the CLI fails / targets the wrong place). Remove the cloud deploy key.

Cutover walkthrough

  1. Run Convex on the Linux host (Docker). Expose API :3210 and site :3211 on the host only — not directly to the public internet.
  2. Cloudflare Tunnel maps convex.mccoidco.xyz → :3210 and convex-site.mccoidco.xyz → :3211. Confirm both hostnames resolve and respond over HTTPS.
  3. Generate an admin key on the host (./generate_admin_key.sh inside the backend container). Store it in a password manager — you need it for CLI and Vercel.
  4. Point the laptop at self-hosted via .env.local (see checklist). Remove or ignore cloud CONVEX_DEPLOYMENT / CONVEX_DEPLOY_KEY so the CLI cannot target cloud by accident.
  5. Import data (export from cloud, strip broken generated_schema.jsonl if needed, import into self-hosted).
  6. Set Auth keys on the self-hosted deployment with node scripts/set-auth-keys.mjs (below). Also set SITE_URL to your Vercel production URL.
  7. Deploy functions once from the laptop: npx convex deploy (uses self-hosted env vars).
  8. Update Vercel env: public Convex URLs + self-hosted deploy pair; delete CONVEX_DEPLOY_KEY. Redeploy.
  9. Smoke-test on cellular / incognito: sign-in, data present, Network tab shows convex.mccoidco.xyz only.

JWT / JWKS key script

Convex Auth needs JWT_PRIVATE_KEY and JWKS on the self-hosted deployment. This script generates an RS256 keypair and sets both via stdin so PowerShell cannot strip JSON quotes.

Run from the repo root with .env.local already pointing at self-hosted (CONVEX_SELF_HOSTED_URL + admin key). After rotating keys, existing sessions break — users must sign in again.

File: scripts/set-auth-keys.mjs

/**
 * Generate Convex Auth JWT keys and set them on the linked deployment.
 * Avoids PowerShell quote-stripping that corrupts JWKS / JWT_PRIVATE_KEY.
 *
 * Usage (from repo root):
 *   node scripts/set-auth-keys.mjs
 */
import { exportJWK, exportPKCS8, generateKeyPair } from "jose";
import { spawnSync } from "node:child_process";
import { writeFileSync, unlinkSync } from "node:fs";
import { tmpdir } from "node:os";
import { join } from "node:path";

const keys = await generateKeyPair("RS256", { extractable: true });
const privateKey = (await exportPKCS8(keys.privateKey))
  .trimEnd()
  .replace(/\n/g, " ");
const publicKey = await exportJWK(keys.publicKey);
const jwks = JSON.stringify({ keys: [{ use: "sig", ...publicKey }] });

function setEnv(name, value) {
  const file = join(tmpdir(), `convex-env-${name}-${Date.now()}.txt`);
  writeFileSync(file, value, "utf8");
  const result = spawnSync(
    "npx",
    ["convex", "env", "set", name],
    {
      input: value,
      encoding: "utf8",
      shell: true,
      stdio: ["pipe", "pipe", "pipe"],
    },
  );
  unlinkSync(file);
  if (result.status !== 0) {
    console.error(result.stdout);
    console.error(result.stderr);
    throw new Error(`Failed to set ${name}`);
  }
  console.log(`Set ${name} OK`);
  console.log(result.stdout.trim());
}

setEnv("JWT_PRIVATE_KEY", privateKey);
setEnv("JWKS", jwks);
console.log("Done. Sign in again with a migrated account.");

Also set SITE_URL

After keys are in place (or separately), point auth cookies at the production UI:

npx convex env set SITE_URL https://refill-livid.vercel.app/

Use your real Vercel domain. Update this if the production hostname changes.
